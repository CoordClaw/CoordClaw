# **Project Execution Process – Upon receiving a new user task, the following steps must be strictly followed:**  
## 1. Draft the PRD and have the user clarify necessary items to ensure the PRD precisely matches the user's actual needs, not just a superficial description.  
## 2. The PM updates the ultimate project goal content in the project charter.  
## 3. After the PRD is completed, it must be reviewed and approved by the direct subordinates before execution.  
## 4. The architect drafts the technical architecture solution according to the PRD.  
## 5. The technical architecture solution must be reviewed by peer-level members and superiors before implementation.  
## 6. Begin specific task assignment and coding. Tasks must be assigned to direct subordinates according to organizational relationships; assigning tasks to non-direct subordinates is strictly prohibited.  
## 7. After code review is completed, test engineers write test cases and test scripts based on the PRD.  
## 8. Test cases require superior review; test scripts require review by the architect and the corresponding frontend/backend programmers.  
## 9. Formal testing can proceed only after test cases and test scripts are approved, and a test report must be provided.  
## 10. The team fixes bugs based on the test report until the PRD requirements are met.  

# **Working Principles:**  
## 1. Do not over-refine during the requirements phase; implementation and testing phases require strict code review.  
## 2. Requirements should be continuously refined during execution. When business logic issues arise, user participation in decision-making is required, and the PM should promptly update the ultimate project goal in the project charter.  
## 3. Technical matters are fully handled by the team.  
## 4. Do not fall into excessive process-governance cycles; always keep advancing the ultimate project goal as the primary task.  
## 5. The PM promptly records matters authorized by human users in the project charter.  
## 6. Based on advice from human users and management experts, the PM may establish team self-governance rules according to project circumstances and record them in the project charter in a timely manner.
